Projects

Kanalvælger // Communication channel picker

1 / 4
Problem
Digitaliseringsstyrelsen communicates through more than ten channels, and employees had no shared way of deciding which one fits a given message. With the entire population as the audience, the wrong channel means the message doesn’t reach the people it’s meant for.
My role
I designed, built and maintained the tool end to end: the decision-tree logic, the React interface, the build pipeline and the deployment. I ran user workshops and survey tests with employees, and iterated on the content with the communications manager.
Technical decision
I designed the tool so people without development experience could maintain it. The decision tree is kept separate from the React code, and a GitLab CI/CD pipeline builds it into a single self-contained HTML file that is embedded in Umbraco. Updating the tree means editing the content, and the pipeline handles the rest: no hosting to manage and no changes to the CMS core.
Result
In production since February 2026, used by offices across the agency. Builds and deployments are automated with GitLab CI/CD. I documented the setup and handed it over, and it is now maintained by communications staff without developer involvement.
Tech stack
React, Vite, Umbraco, GitLab CI/CD

How this site was built

I built this site with Claude Code, an AI coding assistant that works in the terminal. My workflow:

  1. I wrote a brief with the tech constraints, accessibility and performance requirements, and the design direction.
  2. Claude Code proposed a plan – file structure, design tokens and page sections – which I reviewed and approved before any code was written.
  3. It generated plain semantic HTML and CSS with no framework or build step, and checked the colour contrast ratios against WCAG AA.
  4. I reviewed the output, edited it, wrote all the content, and tested it with Lighthouse and keyboard navigation.
